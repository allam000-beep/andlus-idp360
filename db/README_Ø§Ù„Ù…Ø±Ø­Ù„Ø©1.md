# المرحلة 1: مخطّط قاعدة البيانات (SQLite)

## ما أُنجز
صُمّمت قاعدة بيانات علائقية كاملة تحلّ محل التخزين في المتصفح (`window.storage`).

## الملفات
- `db/schema.sql` — مخطّط الجداول والعلاقات والفهارس (20 جدولاً، 11 فهرساً).
- `db/index.js` — وحدة الاتصال (better-sqlite3) + تهيئة المخطّط + بذر الإعدادات الافتراضية.

## لماذا جداول علائقية بدل JSON؟
التخزين القديم كان JSON blobs في المتصفح، وكان سيتجاوز 5MB مع 4000 موظف. الآن:
- كل تقييم صفٌّ مستقل → استعلامات سريعة ومفهرسة.
- علاقات حقيقية بمفاتيح أجنبية → سلامة البيانات مضمونة.
- الحذف المتتالي (CASCADE) → حذف موظف يحذف تلقائياً تقييماته وخططه دون بقايا.

## الجداول الرئيسية
| الجدول | الغرض |
|--------|-------|
| `users` | الحسابات (كلمة المرور bcrypt، لا نص صريح) |
| `user_branches` / `user_stages` | الفروع/المراحل المتعددة للمديرين |
| `peer_assignments` | زملاء التخصص المُقيّمون لكل موظف |
| `eval_scores` | درجات التقييم (rater_id يميّز كل زميل مُقيّم) |
| `eval_witnesses` / `eval_locks` | الشواهد وأقفال الحفظ النهائي |
| `idps` / `idp_rows` | خطط التطور وبنودها |
| `impact_scores` / `impact_witnesses` | قياس أثر التدريب وشواهده |
| `approvals` / `eval_windows` / `edit_requests` | الاعتمادات والنوافذ وطلبات التعديل |
| `internal_courses` / `twice_eval` / `readings` | الدورات الحضورية والتقييم المزدوج والقراءات |
| `settings` | الإعدادات المشتركة (الجدارات، الوظائف، المصادر، الأوزان) كـ JSON |
| `audit_log` | سجل تدقيق أمني (من فعل ماذا ومتى) |

## التحقق
اختُبر المخطّط فعلياً: أُنشئت القاعدة، وتأكّدت العلاقات والقيود (رفض درجة خارج 0-5) والحذف المتتالي — كلها تعمل.

## ملاحظة أمنية
- `password_hash` فقط (bcrypt) — لا كلمات مرور صريحة في القاعدة إطلاقاً.
- ملف القاعدة `*.db` مستثنى من Git عبر `.gitignore`.
