# المرحلة 3: متحكّمات المنطق الكامل (API)

## ما أُنجز
اكتملت كل نقاط الـ API للمنطق، واختُبرت فعلياً — بما فيها أصعب جزء: تقييم الزملاء المتعدّد وإخفاء الهوية على مستوى الخادم.

## المتحكّمات الجديدة
| الملف | الوظيفة |

## منطق تقييم الزملاء (الأهم) — مفروض على الخادم
- المُقيّم يُؤخذ من **رمز الدخول** (لا يُنتحل من الطلب).
- المتوسط لا يظهر إلا بـ **مُقيّمَين فأكثر** (`PEER_MIN_RATERS = 2`).
- `peerRaters` (اسم كل مُقيّم ودرجته) يظهر **للمديرين فقط** (stage_mgr/branch_mgr/admin).
- الموظف/الزميل يرى **العدد والمتوسط فقط** — لا الهوية.

> هذا الإخفاء الآن على مستوى الخادم — أقوى من الواجهة، لا يمكن لأحد تجاوزه بتعديل المتصفح.

## الاختبار الفعلي (أمثلة مما جُرّب)
- ✅ زميل واحد → لا درجة، لكن العدد=1
- ✅ زميلان → المتوسط يظهر بحساب صحيح (4+2)/2=3
- ✅ المدير يرى التفصيل بالأسماء، الموظف لا يراه
- ✅ المدير يُرفض (403) عند محاولة حفظ قياس الأثر (المتابع فقط)
- ✅ الخطط والإعدادات والاعتمادات تُحفظ وتُقرأ
- ✅ كل الملفات سليمة صياغياً (node -c)
