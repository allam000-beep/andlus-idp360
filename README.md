# المرحلة 2: طبقة الخادم والـ API (Express)

## ما أُنجز
بُنيت طبقة الخادم بـ Express مع الأساس الأمني الكامل، واختُبرت فعلياً.

## البنية المجلّدية (كما طلب مسؤول التقنية)
```
andlus-server/
├── app.js                    # الخادم الرئيسي
├── config/
│   ├── index.js              # الإعدادات من .env
│   └── auth.js               # bcrypt + JWT
├── db/
│   ├── schema.sql            # مخطّط القاعدة (المرحلة 1)
│   └── index.js              # الاتصال بالقاعدة
├── middleware/
│   └── auth.js               # حماية المسارات والصلاحيات
├── controllers/
│   ├── authController.js     # تسجيل الدخول
│   └── usersController.js    # CRUD الحسابات
├── routes/
│   ├── auth.js
│   └── users.js
├── public/                   # الواجهة المبنية (المرحلة 3)
├── scripts/                  # سكربتات (بذر، ترحيل)
└── .env.example              # قالب متغيّرات البيئة
```

## معالجة الثغرات الأمنية (ملاحظات مسؤول التقنية)
| الثغرة | المعالجة |
|--------|----------|
| كلمة المرور في الكود | **أُزيلت** — تُخزَّن bcrypt hash في القاعدة، لا نص صريح |
| لا مصادقة حقيقية | **JWT** — رمز موقّع لكل جلسة، بمهلة انتهاء |
| أسرار في الكود | **`.env`** — كل الأسرار خارج الكود (JWT_SECRET إلزامي في production) |
| SQL Injection | **استعلامات مُعامَلة** (prepared statements) في كل مكان |
| هجمات التخمين | **rate limiting** — 20 محاولة دخول كل 15 دقيقة |
| كشف المعلومات | رسالة دخول موحّدة، معالج أخطاء لا يكشف تفاصيل في production |
| رؤوس HTTP | **helmet** — رؤوس أمان قياسية |

## نقاط النهاية (API) الجاهزة
| الطريقة | المسار | الصلاحية | الوظيفة |
|---------|--------|----------|---------|
| POST | `/api/auth/login` | عام | تسجيل الدخول → رمز |
| GET | `/api/auth/me` | مُصادَق | بيانات المستخدم الحالي |
| GET | `/api/users` | مُصادَق | قائمة الحسابات |
| GET | `/api/users/:id` | مُصادَق | حساب واحد |
| POST | `/api/users` | admin | إنشاء حساب |
| PUT | `/api/users/:id` | admin | تعديل حساب |
| DELETE | `/api/users/:id` | admin | حذف حساب |

## الاختبار الفعلي (لم يُكتفَ بالكتابة)
شُغّل الخادم واختُبر:
- ✅ تسجيل الدخول يُصدر رمز JWT
- ✅ الدخول الخاطئ يُرفض (401)
- ✅ المسار المحمي يرفض بلا رمز (401)
- ✅ إنشاء موظف بالرمز يعمل، ولا يُعيد password_hash
